# 决策模型更正：离开网络 vs 网络本身变了

日期：2026-09-16
状态：待 review
取代：`docs/2026-09-16-launchagent-design.md` 第 1 节、第 3 节的状态表与「离家」规则（触发层的机械部分不变：`WatchPaths` + `StartInterval` + 幂等收敛）

> 文档里的 `192.0.2.1`（特征设备）与 `192.0.2.100`（目标设备）取自 RFC 5737 留白段，只是示意。
> 本机真实值只写在 `~/.wifi-loc-control/locations.env` 里，不进仓库（`AGENTS.md` 第 8 节）。

## 1. 要纠正什么

现规则（`AGENTS.md` 约定 5）把**两种完全不同的处境**混成了一种：只要特征设备不可达，就一律「只通知、不回落」。

实测后果（2026-09-16）：把 Wi-Fi 切到手机热点后，位置停在 `Home`，那份静态配置让机器**完全没有网络**，而工具只弹一条通知；又因为 macOS 已无位置 UI，用户只能开终端敲 `scselect Automatic` 才能恢复。规则给了通知，没给能照着做的按钮。

正确的模型要把两件事分开：

| | 特征设备 | 目标设备 |
|---|---|---|
| 配置字段 | `LOCATION_n_IP` / `_MAC` | `LOCATION_n_TARGET_IP` / `_TARGET_MAC` |
| 回答的问题 | 我**在哪张**网络上？ | 这张网**还是我设置里期待的那张**吗？ |
| 不可达意味着 | 你已经不在这张网上了 | 你还在这张网上，但这张网变了 |
| 该做什么 | **回落到默认位置**，让机器在任何网络上都能用 | **通知**，不回落（别把静态设置悄悄换成 DHCP） |

## 2. 目标 / 非目标

**目标**：让「离开已知网络」自动回落到默认位置；同时保留「网络环境变了」时只提醒、不擅自动作的保护。

**非目标**：
- 不改二层探测机制（`/dev/udp` 触发 + `arp -n`，仍不用 ICMP / raw socket）。
- 不改「进入方向自动切换」——那条已经实测通过。
- 不做菜单栏（第 3 阶段）。
- 不做多目标设备（一个位置仍只支持一台目标设备）。

## 3. 配置格式与默认规则

```sh
LOCATION_1_NAME="Home"
LOCATION_1_IP="192.0.2.1"            # 特征设备：用来判断「我在哪张网上」
LOCATION_1_MAC="00:00:5e:00:53:01"

# 可选：目标设备，用来判断「这张网还是不是我设置里期待的那张」
# 省略时默认与特征设备相同
LOCATION_1_TARGET_IP="192.0.2.100"
LOCATION_1_TARGET_MAC="00:00:5e:00:53:02"
```

默认规则（按你的决定）：`_TARGET_IP` 缺省时取 `_IP`；`_TARGET_MAC` 缺省时取 `_MAC`。两者各自独立缺省，但通常一起给。

两个直接推论：

1. **默认下目标设备就是特征设备，两次检查必然同结论**，所以实现上**不要重复探测**——目标 IP/MAC 与特征 IP/MAC 相同时跳过第二次探测。
2. **`Home` 这种情况必须显式配置目标设备**，否则新功能永远不会触发（默认退化成特征设备自己）。现有那份线上配置需要补两行，否则行为与今天完全一样。

非法值与不完整组的处理沿用现状：缺 `NAME`/`IP`/`MAC` 的组跳过并记日志；`_TARGET_*` 单独缺失按默认规则补，不视为不完整。

## 4. 三个状态

按你的提议，`state` 文件从两态（`ok`/`away`）改成三态：

| 状态 | 含义 |
|---|---|
| `default` | 当前在默认位置（`Automatic`）。没有为该网络准备的静态设置，也就没什么可核对的 |
| `ok` | 当前在某个已知位置，**且目标设备在场**——设置与环境一致 |
| `broken` | 当前在某个已知位置，**但环境与设置不符**（目标设备不可达；或特征地址上换了别的设备） |

`state` 仍然只记「**用户当前是否已被告知一个异常状态**」，沿用约定 12 的语义：`ok` / `default` 一律重置；只有**真的送达**了才写 `broken`。旧值 `away` 在升级后按「未知值 = 没通知过」处理（现有失败方向），**不需要迁移脚本**。

## 5. 完整转移表

`F` = 特征设备（地址 + MAC 双匹配），`T` = 目标设备，`cur` = 当前位置，`L` = 命中的位置，`D` = 默认位置。

| # | F | T | cur | 动作 | 新状态 | 通知 |
|---|---|---|---|---|---|---|
| 1 | 命中 | 在场 | `cur == L` | 无 | `ok` | — |
| 2 | 命中 | 不可达 | `cur == L` | 无（不动设置） | `broken` | **进入 `broken` 时通知一次** |
| 3 | 命中 | 在场 | `cur != L` | **切到 `L`**，然后核对 `T` | `ok` | — |
| 4 | 命中 | 不可达 | `cur != L` | **切到 `L`**，然后核对 `T` | `broken` | 同上 |
| 5 | 地址在但 MAC 不符 | — | 任意 | 不切换 | `broken` | 同上（文案说明「地址上的设备换了」）|
| 6 | 不可达 | — | `cur == D` | 无 | `default` | — |
| 7 | 不可达 | — | `cur != D` | **回落到 `D`**（需连续两轮，见 §8） | `default` | 无（见 §7，待你确认）|

第 3/4 行体现你的顺序决定：**先切换、再核对目标设备**——先把机器放到能用的配置上，网络一切正常时用户立刻就能用；有问题才提醒。

第 5 行是一个我替你推导的归类，**请你确认**：特征**地址**被别的设备占用（MAC 不符）算「网络环境变了」而不是「离开了」。依据是你的原话——「网络出现了问题，弹窗提醒用户网络环境出现了变化」。代价：在别人家也用 `192.0.2.1` 的网络里，你只会收到通知、不会自动回落。这是保守的一侧，符合「环境变了就别猜」。反过来说，如果把它归成「离开」，那么家里换了路由器（新 MAC）就会被静默回落成 DHCP，你的静态设置再也不会被使用，而你不会被告知——这正是原约定 5 想避免的掩盖。

## 6. 与既有约定的关系

- **约定 5 重写**（原文见附录）：
  > **自动化做两个方向，但只有「离开」是无条件回落的。** 进入已知位置是自动的；离开所有已知位置时自动回落到默认位置（让机器在任何网络上都能用）；但**在某个已知位置内发现环境与设置不符时，只通知、不回落**——那种改动应当由人确认。
- **约定 4（IP + MAC 双匹配）沿用**，并扩展到目标设备：目标地址上换了设备也算不符。
- **约定 6（幂等）**：回落同样受它约束。回落写入 `SystemConfiguration` 会再触发一轮，那一轮读 `cur == D` + `F` 不可达 → 无动作，收敛。
- **约定 12（去重语义）**：不变，但状态词汇换成 `default`/`ok`/`broken`。
- **约定 2（不需要 root）**：不变，回落仍是 `scselect`。

## 7. 通知策略

- **进入 `broken` 通知一次**，停留不重复（沿用去重）。文案沿用现有隐私约定：不含地址、不含 MAC。
- **回落（第 7 行）不通知，只记日志**——这是待你确认的一点。理由：回落是「你离开了」的正常结果，不是异常；通知会与 `broken` 的提醒混在一起，稀释它的分量。反过来若你希望「位置被改动了要让我知道」，那就该通知。
- 通知文案分两种：目标设备不可达（`Cannot identify the current network...` 的语义换成「设置与环境不符」）与特征地址上换设备（`A configured address answered with an unexpected MAC...`）。

## 8. 回落的安全阀（我建议加，请你定）

**要求特征设备连续两轮不可达才回落。** 依据两条实测：

1. 切换位置**会清空邻居表**，所以「刚切换完」那一轮可能看到**假性缺失**。
2. `10:49:38` 出现过一次连续 8 秒 `no answer`，原因至今未明，且已列为待查项。

不加安全阀的话，一次假性缺失就会回落，下一轮再切回来——**两次接口重配、网络两次瞬断**。代价是真正离开时回落晚一个轮次（有活动时约 60 秒，安静时最多一个 `StartInterval`）。

## 9. 失败模式

| 情况 | 行为 |
|---|---|
| `locations.env` 缺失或所有组非法 | 退出 3，不切换不通知（现状） |
| 目标设备只是短暂无响应 | 探测本身有 4 次 × 1 秒重试；仍失败则进入 `broken` 并通知一次 |
| 回落时 `scselect` 失败 | 退出 1 并记日志（现状） |
| 通知发送失败 | 不写 `broken`，下一轮重试（约定 12） |
| 只有特征设备、没配目标设备 | 目标恒等于特征，第 2/4 行不可达——**行为与今天一致**，属于向后兼容 |

## 10. 验证计划

沿用 `AGENTS.md` 第 6 节的做法（临时配置 + 桩 `osascript`，不真弹通知、不碰真实配置）。新增/修改的断言：

| # | 用例 | 期望 |
|---|---|---|
| N1 | 目标字段省略 | 目标等于特征：命中即 `ok`，不产生第二次探测 |
| N2 | 命中 + 目标在场 | `state=ok`，不通知 |
| N3 | 命中 + 目标不可达（已在 `L`） | `state=broken`，通知**一次**；再跑一轮不重复 |
| N4 | 命中 + 目标不可达（在 `D`） | **先切到 `L`**，再判定 `broken` |
| N5 | 目标恢复 | `state` 回 `ok`，再坏一次会再通知 |
| N6 | 特征不可达 ×1 | **不回落**（安全阀），`state` 不变 |
| N7 | 特征不可达 ×2 且 `cur != D` | **回落到 `D`** |
| N8 | 特征地址 MAC 不符 | `state=broken`，不回落 |
| N9 | 特征不可达且 `cur == D` | 无动作，`state=default` |
| N10 | 旧 `state` 文件内容是 `away` | 按未通知处理，能正常通知 |

端到端（真实系统，需要你配合）：热点场景应**自动回落到 `Automatic`** 并且**不再需要手动敲 `scselect`**；回家后应自动切回 `Home`。

## 附录：约定 5 原文（将被替换）

> **自动化只做「进入」方向。** 从 `Automatic` 切到识别出的位置是自动的；从非默认位置退出**只通知、不自动切**。理由是二层层面「设备消失」可能意味着真实配置变动，不该由脚本猜。
